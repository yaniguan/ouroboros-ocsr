# Oct 30: real-image fine-tune (VERDICT-PMC) with real-validation checkpoint selection

Branch `feat/real-finetune-oct30` (from `feat/rgroups-aug-oct29` @ b49ce75). No GPU training was run
here; everything below was measured on the 2-CPU box unless marked as an estimate.

## Why

The Oct 29 Colab fine-tune (synthetic real-aug shards only, `real_fraction 0`, lr 3e-5, 2000 steps,
batch 8, `rotation_aug: true`, selection on synthetic val) took A from 18.12% to 8.39% and C from
16.78% to 13.76% exact on the 298 real test images. Synthetic val (25% exact) did not predict real
accuracy. Two changes address that directly: train on real document crops, and select checkpoints by
exact match on real images. A third: A was released without rotation augmentation and every real
test image is upright, so the new config sets `rotation_aug: false`.

## What changed

- `scripts/prepare_pmc.py`: HF parquet (image struct + `smiles`) -> manifest for `ingest_real.py`.
  Standardizes every label with the harness standardization, drops (with counted reasons) rows whose
  leakage-key connectivity block is a held-out test molecule (both splits), unparsable/untokenizable
  labels, labels longer than the decoder (`len(encode)-1 > 128`), and val molecules also in PMC train
  (`val_in_train`, so validation measures new-molecule generalization like the test set). Val rows are
  written in seeded random order so the Trainer's validation prefix is a random article mix.
- `scripts/check_leakage.py`: `--fail-on-connectivity` (exit 1 on any connectivity-block overlap,
  i.e. stereoisomers too) and `--json`.
- `Trainer`: `validation.at_start` scores the initial (released) weights at step 0, so selection can
  fall back to them; `validation.keep_only_best` prunes superseded `best-step-*.pt`; the start log
  records `real_fraction` and `n_validation`. The existing `real_roots`/`real_fraction` mixture and
  `exclude_keys` paths worked unchanged (verified with real PMC shards).
- `scripts/prepare_real_finetune.py`: per-arm append-only vocabulary (released IDs unchanged + alias
  tokens + tokens of synthetic and **PMC train** labels; real val/test never shape it) and run config
  (released architecture, bf16 when supported, `validation.samples` clipped to available rows).
- `configs/finetune-real-pmc.yaml`: real_fraction 0.6, lr 1.5e-5, warmup 100, cosine, 3000 steps,
  batch 16, no rotation aug, real val 400 images every 250 steps, patience 4, min_delta 0.0025.
- `colab/finetune_real_pmc.ipynb` (generated by `scripts/make_real_pmc_nb.py`): Run-all pipeline,
  Drive caching/resume, leakage gate, A then C, optional LR sweep per arm selected by real val.
- `tests/test_real_finetune.py`: PMC preparation filters, connectivity leakage gate, exact real
  fraction in the mixture, step-0 validation, best pruning, resume without duplicate validation.

## Colab `python -m ouroboros.train` exit status 1 (finetune_real_pmc) — root cause and fix

Reproduced on CPU (2-vCPU box, Python 3.11 venv, torch 2.10.0+cpu) with the notebook's exact
sequence: `prepare_real_finetune.py ... --set ... data.num_workers=8 train.device=cpu` on
`runs/real-aug-smoke/shards` + `real/pmc_smoke`, then `python -m ouroboros.train`. It exited 1
after ~12 s with:

    RuntimeError: Caught UnicodeDecodeError in DataLoader worker process 1.
      File "ouroboros/data/loader.py", line 145, in __getitem__
        meta = json.loads(self._read(shard, s["json"]))
    UnicodeDecodeError: 'utf-8' codec can't decode byte 0x89 in position 512

Cause: `ShardDataset` opens shard file handles lazily in `_read`, and with `data.exclude_keys`
set its `__init__` reads every sample's metadata, so handles are already open in the parent.
DataLoader workers are forked on Linux (no pickling, so `__getstate__` never resets `_fh`) and
inherit those file objects; all workers then share one OS file offset, and concurrent
`seek()` + `read()` return bytes of other members (PNG magic `0x89` parsed as JSON). Earlier
smoke runs and the tests used `num_workers=0`, which hid it.

Fix: handles are keyed to the opening PID (inherited ones are dropped in a child) and reads use
`os.pread` (explicit offset, no shared position); short reads raise. After the fix the same
command completed 5 steps with validation at steps 0/2/4/5 (exit 0, 39.8 s), and re-running it
resumed at step 5 and returned (3.0 s). Regression test `tests/test_loader_workers.py` fails on
the old loader and passes on the new one.

Notebook: `run()` now streams merged stdout+stderr, reprints the last 80 lines on failure and
keeps the full log on Drive (`<run>/train_stderr.log` for training, `logs/` otherwise); the
train cell skips runs whose `train/ckpt/last.pt` reached `train.steps` or early-stopped.
